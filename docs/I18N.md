# Internationalization (i18n)

OrbitTLM keeps all user-facing translation data in the source-controlled `i18n/` locale files. Translations are not defined as Chinese/English replacement pairs in C++ code.

## Locale file structure

- `code`: locale identifier (`zh-CN` or `en-US`).
- `displayName`: the language name shown in the language menu.
- `translations`: map whose keys are the original Chinese source strings. `zh-CN.json` maps each key to itself; `en-US.json` maps the same keys to English. Keep format placeholders such as `%1`, `%2`, and newline positions compatible between source and target values.
- `webTranslations`: source/target replacements for the static HTML history page. This separate map can contain HTML or JavaScript source snippets whose visible labels need localization. The source snippets are preserved unchanged as values in `zh-CN.json`.

## Embedded resources

`CMakeLists.txt` uses `qt_add_resources(orbittlm_ui orbittlm_i18n ...)` to compile both JSON files into the OrbitTLM UI resource collection. At runtime, the application reads `:/i18n/zh-CN.json` and `:/i18n/en-US.json`, so the built application does not depend on a loose `i18n/` directory beside the executable.

## Validation

Run this command from the project root after changing locale strings:

```bash
python tools/validate_i18n.py
```

The validator checks JSON syntax, source-key parity between locales, preserved Chinese originals, missing translations for C++ Chinese string literals and telemetry-tree catalog labels, English values containing Chinese text, and the English HTML history output including its built-in fallback template. It also verifies that both locale files are listed as embedded Qt resources. The test suite checks representative telemetry labels and validates that the dictionaries are present in the compiled Qt resource system.
